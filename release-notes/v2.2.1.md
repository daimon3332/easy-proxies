## What's Changed

- Site connectivity checks now support a per-run timeout from 1 to 60 seconds while keeping the existing 10-second default.
- The selected timeout consistently applies to each site's HTTP request, TLS handshake, response-header wait, and retry attempt.
- The WebUI persists the timeout preference locally, displays the active value in job progress, and locks the control while a job is running.
- Invalid values are reported inline and rejected by the server; they cannot start a detection job.
- Fixed site selectors and the timeout control remaining disabled after a detection job finishes.
- Added regression coverage for the default, boundaries, request decoding, timeout propagation, retry behavior, and WebUI wiring.
- Release packages are provided for Windows and Linux. Each platform includes amd64 and arm64 binaries and ZIP packages, plus SHA-256 checksums.
