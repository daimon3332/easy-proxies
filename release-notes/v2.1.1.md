## What's Changed

- Subscription fetching now tries the direct connection first and only falls back to a bounded number of available pooled proxies for transient failures. Each attempt has a complete timeout budget, response bodies are limited to 10 MB, and reported errors no longer expose sensitive URLs.
- Node probing now runs for at most three rounds and retries only transient failures. Later rounds contain only failed nodes, avoiding repeated tests of nodes that have already passed.
- Tagged imports and refreshes are now transactional. A failed source keeps its previous usable nodes, successful sources are applied independently, and revision checks prevent stale jobs from overwriting newer results.
- Runtime application now exposes explicit apply and verify phases. Listener verification retries only failed ports up to three times and confirms that passed nodes, pool entries, generated configuration, and listening ports converge to the same final set.
- Fixed staged nodes being counted as successful before final cleanup, which could leave the displayed success count inconsistent with available ports.
- Fixed partial refresh results being reported as failed even when valid nodes were successfully applied.
- Refresh progress details now preserve their scroll position while live updates are rendered.
- Added regression coverage for direct and fallback subscription fetching, retry classification, source rollback, stale revisions, staged-node cleanup, partial application, and runtime listener convergence.
- Release packages are provided for Windows and Linux. Each platform includes amd64 and arm64 binaries and ZIP packages, plus SHA-256 checksums.
